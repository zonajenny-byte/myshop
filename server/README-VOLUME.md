# 掛 Railway Volume：解決重新部署資料消失的問題

## 為什麼會發生

Railway（還有大多數雲端平台）每次重新部署，都是**整個容器重建**——不是「更新程式碼、保留其他東西」，而是砍掉整個環境重來一次。後台上傳的商品照片、編輯過的 AI 工具內容、發布的文章，這些都存在容器的檔案系統裡，重新部署後容器整個消失，資料就跟著不見了。

商品的文字資料（訂單、折扣碼⋯⋯）也是一樣的處境，只是比較不容易注意到——因為那些欄位重建後會退回程式碼裡的初始種子資料，看起來像「還在」，但你後台改過的東西其實已經沒了。

## 解法：掛一個 Volume

Volume 是 Railway 提供的持久保存空間，不會因為重新部署而清空。這次的程式碼改動已經讓所有資料（商品、訂單、折扣碼、文章、AI 工具編輯、上傳的圖片）統一寫進同一個目錄，接下來只要把這個目錄指到 Volume 就完成了。

### 步驟

1. Railway 專案裡，點進你的後端服務
2. 左側或上方找 **Volumes** 分頁（不同版面可能在 Settings 底下）
3. 點 **New Volume** / **+ Add Volume**
4. **Mount Path** 填 `/app/data`（或你喜歡的路徑都可以，程式會自動偵測，不用跟這裡的範例一模一樣）
5. 建立，Railway 會自動重新部署這個服務

### 怎麼確認成功

重新部署完，看 **Deploy Logs**，應該找不到任何錯誤。接著實際測試：

1. 進後台，上傳一張商品照片、改一段 AI 工具的介紹文字
2. 回 Railway，手動觸發一次 **Redeploy**（模擬下次你更新程式碼時會發生的事）
3. 重新整理網站，剛才傳的照片、改的文字應該都還在

如果都還在，就代表接成功了。

### 沒有掛 Volume 會怎樣

程式碼會自動退回原本的行為（資料寫在容器裡，重新部署會消失），**不會報錯，也不會壞掉**——只是又回到現在的狀況。所以沒掛之前不用擔心程式碼本身出問題，掛的時機你自己決定就好。

### 技術細節（給之後維護的人看）

所有資料存取都透過 `server/lib/dataDir.js` 這支檔案決定路徑。它會優先讀取 Railway 自動注入的 `RAILWAY_VOLUME_MOUNT_PATH` 這個環境變數（掛 Volume 時 Railway 自己會設定，不用手動填），沒有的話才退回 `server/` 目錄本身。

也就是說：**你在 Railway 後台選的 Mount Path 是多少完全不重要**，程式會自動抓到那個值並使用，不需要额外設定任何自訂環境變數，也不用改任何程式碼。

如果之後要換成真正的資料庫（SQLite、Postgres），這九個檔案（`store.js`、`orders.js`、`entitlements.js`、`subscriptions.js`、`discountCodes.js`、`announcement.js`、`articles.js`、`skillOverrides.js`、`index.js`）都是入口，每支的讀寫邏輯（`load()`/`save()`）介面單純，換掉不難。
